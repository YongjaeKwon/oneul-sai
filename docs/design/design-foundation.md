### 다크 (앱 화면 전용, 마케팅에는 없음)

바탕은 브라운을 어둡게 내린 `#1B1412`, 글자는 아이보리 `#F1E7E2`, 로즈는 약간 밝힌 `#E39A97`. 단순 반전이 아니라 "밤의 카페" 톤. 값은 `theme.css`의 `prefers-color-scheme: dark` 블록이 원천.

### 대비 규칙 (접근성)

- 로즈 계열(`rose`, `rose-deep`)은 `paper` 위에서 대비가 2.5~2.9:1이라 큰 글자 기준(3:1)에도 못 미친다. **글자에는 쓰지 않고** 장식 · 배경 · 밑줄에만 쓴다. 로즈 글자는 크기와 관계없이 `rose-ink`(`paper` 위 5.8:1, `rose-wash` 위 4.6:1)를 쓴다.
- `ink-muted`는 `paper` 위에서 대비가 약 3:1이다(`ivory` 위 2.8:1). **`paper` · `surface` 위의 큰 글자(24px 이상), 비활성, 장식(점 · 뒤 배경)에만** 쓴다. `ivory` 위에서는 큰 글자에도 쓰지 않는다. 작은 캡션 · 안내 문장 · 입력 칸 placeholder는 `ink-soft`(`paper` 위 약 5.3:1)를 쓴다. 브랜드 원색이라 값은 바꾸지 않는다.
- 본문과 `primary` · `secondary` 버튼 글자는 `ink` 계열, `ghost` 버튼 글자는 `rose-ink`를 쓴다. 기본 버튼은 **딥 브라운 배경 + 아이보리 글자**(대비 약 10:1). "로즈 버튼에 흰 글자"는 만들지 않는다.
- 상태 색은 아이콘·테두리와 함께 쓰고, 색만으로 의미를 전달하지 않는다.

## 3. 글꼴

팜플렛은 모두 세리프(명조)지만, 앱 UI의 표·폼·긴 목록은 산세리프가 읽기 쉽다. 그래서 **제목은 명조, 본문은 산세리프**로 나눈다.

| 역할            | 글꼴                                   | 토큰 / 유틸리티                               | 사용처                                                                                  |
| --------------- | -------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------- |
| 한글 제목       | **Noto Serif KR** (400·600·700)        | `--font-display` / `font-display`             | h1~h3, 카드 제목, 이벤트 이름                                                           |
| 라틴 디스플레이 | **Playfair Display** (400·700, 이탤릭) | `--font-latin-display` / `font-latin-display` | TODAY · ONE MORE · AFTER · NEXT, ONULSAI, 라운드 번호                                   |
| 본문·UI         | **Noto Sans KR** (400·500·700)         | `--font-sans` / `font-sans`                   | 문장, 버튼, 폼, 표                                                                      |
| 숫자            | 본문 글꼴 + `tabular-nums`             | `tabular-nums`                                | 정원 9/10, 시간, 금액                                                                   |
| 날짜 숫자       | 명조 + `tabular-nums`                  | `font-display tabular-nums`                   | 일정 카드 · 상세의 일시, 운영자 회차 목록 · 미리보기의 일시, 여러 회차 등록의 고른 날짜 |

- 웹은 `next/font/google`로 싣고 CSS 변수(`--font-noto-sans-kr` 등)로 `theme.css`에 연결한다. 세 변수 이름은 web·admin·theme.css가 같아야 한다.
- 모바일(React Native)은 같은 글꼴 파일을 `expo-font`로 싣는다(Step 1에서 앱 화면이 생길 때 적용).
- 영문 대문자 라벨은 자간을 넓게: `tracking-[0.2em]`~`[0.35em]`. 팜플렛의 "TODAY · ONE MORE · AFTER · NEXT"가 기준.
- 크기 단계(웹): 12 / 14 / 16 / 18 / 24 / 32 / 48px. 이 밖의 값은 쓰지 않는다. 본문 줄 높이 1.65.

## 4. 구성 원칙 (팜플렛에서 가져온 것)

1. **중앙 정렬과 여백.** 팜플렛은 모든 요소가 가운데 정렬이고 위아래 여백이 넉넉하다. 랜딩·확정·결과처럼 "한 가지 메시지" 화면은 같은 구성을 따른다. 목록·폼·관리자 화면은 왼쪽 정렬로 실용성을 우선한다.
2. **짧은 로즈 구분선.** 제목 아래 `1px × 64px` 가운데 선(`line-strong`). 섹션을 나눌 때 큰 박스 대신 이 선을 쓴다. 관리자 화면처럼 왼쪽 정렬인 화면에서는 제목 아래 왼쪽에 둔다(`Divider variant="accent" className="ml-0"`).
3. **브러시 하이라이트.** 핵심 단어 뒤에 `rose-wash` 붓 자국 (CSS로는 `bg-rose-wash`에 살짝 기울인 pseudo-element). 한 화면에 한 곳만. 글자색은 `ink` 그대로 둔다 — `rose-deep` 글자를 `rose-wash` 위에 올리면 대비가 약 2.3:1이라 2절 기준에 못 미친다.
4. **키워드 → 한 문장 → 설명 3줄.** 팜플렛 한 장의 구조. 안내·온보딩 화면은 이 순서를 지킨다.
5. **페이지 표기 "1 / 5".** 여러 단계로 된 흐름(라운드 진행)에서는 세리프 소형 숫자 + 짧은 밑줄로 현재 위치를 보여준다.
6. **카드는 아끼기.** 카드 표면은 `surface` + `line` 1px 테두리, 그림자 없음. 한 화면에 카드 안 카드를 만들지 않는다.
7. **모서리.** 카드 16px(`rounded-card`), 버튼·입력 12px(`rounded-control`), 배지 999px. 그 밖의 반지름은 쓰지 않는다.

## 6. 문구 톤

알림톡과 팜플렛의 말투가 기준이다.

- 정중한 존댓말, 짧은 문장. "만나보세요." "연결됩니다." "안내드릴게요."
- 신뢰 문구는 그대로 반복한다: "서로 선택한 경우에만 연결됩니다." / "양쪽 모두 원할 때만 연결됩니다."
- 시스템 용어를 사용자에게 보이지 않는다: "Application" → "참가 신청", "Match" → "연결", "Preference" → "호감 선택".
- 알림 문구 형식(알림톡 원문 기준): `[오늘사이 참가 확정]` 같은 대괄호 제목 → 이름 호명 → 사실(날짜·시간) → 다음 안내 → 준비물 → 따뜻한 마무리 한 줄.
- 실패·오류 문구도 같은 톤: 사과보다 "지금 상태"와 "다음 행동"을 말한다. "입금 확인 전입니다. 확인되면 알림톡으로 알려드릴게요."

## 7. 모바일(React Native) 적용 방침

`packages/ui`는 웹 전용이다(스펙: RN UI를 웹과 억지로 통합하지 않음). 모바일은 다음 방식으로 같은 세계를 유지한다.

- 색·간격·반지름 값을 TypeScript 상수로 공유: Step 1에서 `packages/constants` 또는 새 `packages/design-tokens`(결정 예정)에 `theme.css`와 같은 값을 둔다. **원천은 이 문서**, 두 코드가 이 문서를 따른다.
- 글꼴은 `expo-font`로 Noto Serif KR / Noto Sans KR을 싣는다.
- 컴포넌트는 RN 네이티브로 따로 만들되 이름·변형(primary/secondary/ghost)은 웹과 같게 한다.

## 10. 외부 디자인 스킬과 부딪칠 때

이 문서가 이긴다(AGENTS.md 6장 "외부 스킬 · MCP"). 알려진 충돌:

- **Taste**: 세리프 비권장, `paper` · `ivory` · `ink` 계열 팔레트 금지, 소비자 페이지 다크 강제, "1 / 5" · 가운데 점 라벨 금지 → 모두 따르지 않는다(Noto Serif KR · Playfair Display, 2절 색, 마케팅은 라이트, `TODAY · ONE MORE · AFTER · NEXT` 유지).
- **Emil**: 누를 때 축소(`:active`의 `scale(0.97)`), 전환 중 blur, Framer Motion 예시 → 모션 라이브러리는 들이지 않고 CSS로만 한다. `Button`에 `:active` 축소를 넣으려면 5절 표를 같은 PR에서 고친다.
- **Impeccable**: 대담한 재디자인 쪽 지시, 그림자 · 반투명 · blur로 깊이를 주라는 기준(`craft-floor`) → 따르지 않는다(카드는 `surface` + `line` 1px, 그림자 없음). 검사 엔진의 `cream-palette`(2절 `paper` 바탕) 지적은 브랜드 색이라 무시한다. 1절(정중함) · 8절이 우선.
- 모션 easing · duration 토큰은 아직 없다. 두 곳 이상 쓰게 되면 이 문서와 `theme.css`에 먼저 정한다.
