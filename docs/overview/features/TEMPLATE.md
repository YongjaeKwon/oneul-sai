# 기능 이름

> 이 파일을 `kebab-case.md`로 복사해 쓰세요. 인용문(`>`)은 작성 힌트이니 채운 뒤 지웁니다. 개발자가 아닌 분이 읽는 문서입니다. 기술 용어, 서비스 이름, 테이블 이름은 쓰지 않습니다. 문체는 정중한 존댓말로, 짧고 따뜻하게 씁니다.

- 상태: 초안
- 최종 갱신: YYYY-MM-DD
- 관련 Step: Step N
- 팜플렛 개념: TODAY / ONE MORE / AFTER / NEXT / 운영 기능 중 하나

## 1. 이 기능은 무엇인가요

> 한 문장으로. 참가자 입장에서 "무엇을 할 수 있다"로 끝나게 씁니다. 예: "오늘 만난 7명 중 마음에 드는 분을 선택하고, 서로 선택한 경우에만 연결됩니다."

## 2. 누가 쓰나요

> 참가자 / 운영자 중 누가, 어떤 상황에서 쓰는지. 둘 다 쓰면 나눠 적습니다.

| 누가   | 언제 |
| ------ | ---- |
| 참가자 |      |
| 운영자 |      |

## 3. 화면과 흐름

> 사용자가 보는 순서대로 번호를 붙입니다. 화면 이름은 사용자가 보는 이름으로. 알림을 받는 시점도 넣습니다. 화면 그림이 있으면 링크합니다.

1. …
2. …
3. …

## 4. 규칙

> 사용자가 알아야 할 규칙을 짧은 문장으로 나열합니다. 팜플렛의 약속 문구는 그대로 씁니다. 아직 정해지지 않은 규칙은 "결정 예정 (Step N)"이라고 씁니다.

- 서로 선택한 경우에만 연결됩니다.
- …

## 5. 자주 묻는 질문

> 운영자가 참가자에게 실제로 받는 질문, 또는 받을 것 같은 질문. 답은 두세 문장 안으로.

**Q.** …

**A.** …
