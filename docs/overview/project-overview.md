# 오늘사이 프로젝트 개요

> 오늘, 우리 사이의 시작.

- 상태: 초안(리뷰 후 확정)
- 최종 갱신: 2026-09-23 (Step 0 · Step 1 완료, Step 2 설계 중)

이 문서는 오늘사이가 어떤 서비스인지, 시스템이 어떻게 이루어져 있는지를 정리한 소개서입니다. 처음 합류한 누구나 읽을 수 있게 썼습니다. 개발자뿐 아니라 운영자와 디자이너도 독자입니다. 전문 용어는 처음 나올 때 괄호 안에 한 줄로 풀어 씁니다. 자세한 뜻은 [용어 사전](./glossary.md)에 모아 두었습니다.

---

## 1. 오늘사이는 무엇인가

오늘사이(ONULSAI)는 오프라인 로테이션 소개팅(정해진 시간마다 자리를 옮겨 여러 사람과 차례로 1:1 대화하는 방식) 서비스입니다. 일요일의 편안한 카페에서 7명의 새로운 사람과 한 사람씩 1:1로 대화합니다. 프로필만 보는 것이 아니라 직접 만나고 이야기하며 나와 잘 맞는 사람을 찾습니다. 대화가 끝나면 마음에 든 사람을 선택하고, 서로 선택한 경우에만 연결됩니다. 로고의 겹치는 두 원처럼, 두 사람이 만나는 그 "사이"를 만드는 것이 오늘사이의 일입니다.

팜플렛은 이 서비스를 네 개의 단어로 설명합니다. 이 순서가 곧 참가자가 겪는 순서입니다.

| 개념         | 한 줄 소개                        | 어떻게 이어지나                                                                                                                                                   |
| ------------ | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TODAY**    | 오늘, 직접 만나보세요.            | 7명 1:1 로테이션 → 당일 호감 선택 → 서로 선택한 경우에만 연결                                                                                                     |
| **ONE MORE** | 아쉬운 사람이 있었다면, 한 번 더. | 당일 선택이 엇갈렸더라도 집에 돌아간 뒤 생각나는 사람이 있다면, 오늘 만난 사람 중 딱 한 사람에게 한 번 더 마음을 전달. 상대방도 원할 때만 연결                    |
| **AFTER**    | 오늘 없었다면, 다음 인연까지.     | 원하는 사람을 못 만났다면 희망하는 참가자에 한해 AFTER에 등록. 앞으로 조건이 잘 맞는 새로운 사람이 찾아오면 오늘사이가 다시 소개를 제안. 양쪽 모두 원할 때만 연결 |
| **NEXT**     | 새로운 만남으로, 다시 한 번.      | 이번에 인연을 만나지 못했다면 재참가 혜택으로 다시 시작. 새로운 일요일, 새로운 7명                                                                                |

## 2. 참가자의 여정

참가자가 오늘사이를 경험하는 순서입니다. 각 단계 뒤에는 그 일을 맡는 서비스의 이름을 적어 두었습니다(4장에서 설명합니다). 표 안의 "이벤트 서비스"는 행사를 뜻하는 서비스 이름이고, 시스템 메시지인 Kafka 이벤트와는 다릅니다([용어 사전 5장](./glossary.md#5-헷갈리기-쉬운-말)).

| 순서 | 단계             | 무슨 일이 일어나나                                                                                                                                                                                                                                          | 맡는 서비스             |
| ---- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 1    | 가입             | 참가자 웹에서 이메일 · 비밀번호 · 실명 · 출생연도(만 19세 이상) · 성별 · 휴대폰 번호와 필수 동의(개인정보 수집 · 이용)로 가입합니다. 실명과 출생연도는 행사 당일 신분증과 대조하므로 신분증과 같게 적습니다. 온라인 본인인증은 결정 예정(1단계 이후)입니다. | 회원 서비스             |
| 2    | 참가 신청        | 원하는 일요일 일정을 골라 신청합니다.                                                                                                                                                                                                                       | 이벤트 서비스           |
| 3    | 입금 / 결제      | 현재는 계좌이체로 입금하고 운영자가 확인합니다. 카드 결제(PG, 결제 대행사 연동)는 4단계 이후입니다.                                                                                                                                                         | 결제 서비스             |
| 4    | 참가 확정 알림   | 입금이 확인되면 카카오 알림톡으로 참가 확정 안내를 받습니다.                                                                                                                                                                                                | 알림 서비스             |
| 5    | 행사 전 안내     | 정확한 장소와 준비 사항(신분증 지참 등)을 행사 전에 다시 안내받습니다.                                                                                                                                                                                      | 알림 서비스             |
| 6    | 당일 체크인      | 행사 장소에서 신분증으로 출생연도와 본인을 확인하고 입장합니다.                                                                                                                                                                                             | 이벤트 서비스           |
| 7    | 7명 1:1 로테이션 | 정해진 시간마다 자리를 옮겨 7명과 한 사람씩 대화합니다.                                                                                                                                                                                                     | 이벤트 서비스           |
| 8    | 호감 선택        | 대화가 끝나면 마음에 든 사람을 선택합니다.                                                                                                                                                                                                                  | 매칭 서비스             |
| 9    | 연결             | 서로 선택한 경우에만 연결됩니다. 결과를 알려 드리는 방법은 결정 예정(6~7단계)입니다.                                                                                                                                                                        | 매칭 서비스             |
| 10   | ONE MORE         | 행사가 끝난 뒤에도 생각나는 사람이 있다면, 오늘 만난 사람 중 딱 한 사람에게 한 번 더 마음을 전달합니다. 당일 선택이 엇갈렸어도 괜찮습니다. 상대방도 원할 때만 연결됩니다.                                                                                   | 매칭 서비스             |
| 11   | AFTER            | 원하는 사람을 만나지 못했다면, 희망하는 분만 AFTER에 등록합니다. 조건이 잘 맞는 새로운 사람이 오면 오늘사이가 다시 소개를 제안합니다. 양쪽 모두 원할 때만 연결됩니다.                                                                                       | 매칭 서비스             |
| 12   | NEXT             | 재참가 혜택으로 새로운 일요일, 새로운 7명과 다시 시작합니다.                                                                                                                                                                                                | 결정 예정(2 또는 4단계) |

4번 "참가 확정 알림"에서 실제로 발송되는 알림톡 문구입니다. 이 문구가 오늘사이의 말투입니다. 정중한 존댓말, 짧고 따뜻한 문장, 신뢰를 약속하는 표현. 화면 문구를 쓸 때도 이 톤을 기준으로 삼습니다.

> **[오늘사이 참가 확정]**
> [이름]님, 입금이 확인되어 10/4(일) [14:00] 참가가 확정되었습니다.
> 정확한 장소와 준비 사항은 행사 전에 다시 안내드릴게요.
> 행사 당일에는 출생연도와 본인 확인이 가능한 신분증을 지참해 주세요.
> 함께하게 되어 반갑습니다!

## 3. 운영자의 여정

운영자는 운영자 웹(admin)에서 아래 순서로 일합니다. 지금은 대부분 사람이 손으로 하는 일이며, 시스템은 이 순서를 그대로 화면으로 옮기는 것을 목표로 합니다.

| 순서 | 단계             | 하는 일                                                                                                                                                                                                   | 맡는 서비스                                 |
| ---- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 1    | 일정 등록        | 모임 상품(소개팅의 형식·가격 틀)과 일요일 일정(날짜·시간·장소)을 등록하고 정원을 정합니다. 정원은 성별로 나누어 관리할 예정입니다. 세부 규칙과 정원의 위치(상품인지 일정인지)는 결정 예정(2~3단계)입니다. | 이벤트 서비스                               |
| 2    | 신청 관리        | 들어온 신청을 확인하고 취소·정원 초과를 처리합니다.                                                                                                                                                       | 이벤트 서비스                               |
| 3    | 입금 확인        | 계좌 입금을 확인해 신청을 "참가 확정"으로 바꿉니다. 이때 확정 알림톡이 나갑니다.                                                                                                                          | 결제 · 이벤트 · 알림 서비스                 |
| 4    | 행사 전 안내     | 정확한 장소와 준비 사항을 참가자에게 다시 안내합니다.                                                                                                                                                     | 알림 서비스                                 |
| 5    | 당일 진행        | 현장에서 체크인(신분증 확인)을 받고, 라운드(한 사람과 대화하는 한 차례)를 넘기며 로테이션을 진행합니다.                                                                                                   | 이벤트 서비스                               |
| 6    | 결과 · 연결 관리 | 호감 선택 결과와 연결을 확인합니다. ONE MORE 전달, AFTER 재소개 제안, NEXT 재참가 혜택을 관리합니다.                                                                                                      | 매칭 서비스(NEXT는 결정 예정, 2 또는 4단계) |

## 4. 시스템은 어떻게 이루어져 있나

오늘사이 시스템은 크게 "사람이 보는 앱 3개"와 "뒤에서 일하는 서비스 6개"로 이루어져 있습니다.

### 사람이 보는 앱

| 앱                        | 누가 쓰나 | 설명                                                                                                                                                 |
| ------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 참가자 웹 (`apps/web`)    | 참가자    | 일정을 보고 신청하는 화면입니다. 호감 선택을 어디서 받을지는 결정 예정(6단계)입니다.                                                                 |
| 참가자 앱 (`apps/mobile`) | 참가자    | 스마트폰 앱입니다. 웹이 주(가입 · 신청 · 결제)이고 앱은 행사 당일(체크인 · 라운드 · 호감 선택) 중심입니다. 앱 로그인은 5단계(SPEC-005)에서 만듭니다. |
| 운영자 웹 (`apps/admin`)  | 운영자    | 일정 등록부터 당일 진행, 결과 관리까지 운영 업무 전용 화면입니다.                                                                                    |

### 뒤에서 일하는 서비스

서비스(마이크로서비스)는 눈에 보이지 않는 곳에서 한 가지 일을 맡아 돌아가는 작은 프로그램입니다. 회사의 부서에 비유하면 이해가 쉽습니다.

| 서비스                               | 비유        | 맡는 일                                                                                                                                                                                                                                                                                        |
| ------------------------------------ | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 게이트웨이 (`api-gateway`)           | 안내 창구   | 앱이 서버에 말을 걸 때 거치는 하나의 창구입니다. 요청을 알맞은 부서로 넘겨 주고, 로그인 증표를 확인해 "누가 보낸 요청인지"를 부서에 알려 주며, 한 곳에서 요청이 너무 많이 오면 막습니다. 스스로 업무 판단(비즈니스 로직)은 하지 않습니다. 결제 대행사 PG와는 이름만 비슷한 전혀 다른 것입니다. |
| 회원 서비스 (`member-service`)       | 회원 관리부 | 가입, 로그인, 프로필, 비밀번호 변경, 탈퇴, 계정 상태(운영자의 정지 · 해제)를 맡습니다. 1단계에서 만들었습니다([기능 소개서](./features/signup-login.md)). 온라인 본인인증은 결정 예정(1단계 이후)입니다. 현장 본인 확인은 이벤트 서비스의 체크인에서 합니다.                                   |
| 이벤트 서비스 (`event-service`)      | 행사 운영부 | 모임 상품, 일정, 참가 신청, 정원, 참가자, 체크인, 로테이션까지 "행사 운영" 전체를 맡습니다. 이름의 "이벤트"는 행사를 뜻합니다.                                                                                                                                                                 |
| 매칭 서비스 (`matching-service`)     | 인연 담당   | 호감 선택을 받아 서로 선택했는지 판별하고, 연결(매칭) 결과를 만듭니다. ONE MORE·AFTER도 여기서 다룹니다.                                                                                                                                                                                       |
| 알림 서비스 (`notification-service`) | 안내 담당   | 알림톡(지금 쓰는 채널)을 보내고, 앞으로 푸시·문자·이메일도 보냅니다. 발송 기록을 남깁니다.                                                                                                                                                                                                     |
| 결제 서비스 (`payment-service`)      | 회계 담당   | 결제 요청, 승인, 취소, 상태를 관리합니다. 초기에는 운영자의 입금 확인 기반이고, PG 연동은 4단계 이후입니다.                                                                                                                                                                                    |

### 각 서비스는 자기 장부만 갖는다

게이트웨이를 뺀 다섯 서비스는 저마다 자기 장부(데이터베이스)를 하나씩 갖습니다. 회원 서비스의 장부는 회원 서비스만 읽고 씁니다. 다른 서비스가 몰래 들여다보는 일은 없습니다. 다른 부서의 정보가 필요하면 약속된 두 가지 방법으로만 묻습니다.

- **직접 질문(REST API)** — 지금 바로 답이 필요할 때 씁니다. 앱 → 게이트웨이 → 서비스 순서로 흐릅니다.
- **게시판(Kafka 이벤트)** — "이런 일이 있었어요"라고 붙여 두면 관심 있는 부서가 가져가 읽습니다. 답을 기다리지 않는 후속 일에 씁니다. 예: 입금이 확인되면 알림 서비스가 그 소식을 읽고 알림톡을 보냅니다.

질문과 답의 형식은 계약(Contract)이라는 공용 문서에 미리 적어 둡니다. 모두가 그 형식만 따릅니다.

### 왜 이렇게 나눴나

가장 큰 이유는 "행사 당일 현장이 멈추지 않게" 하기 위해서입니다.

- **현장은 멈추지 않습니다.** 카카오 알림톡 서버가 멈춰도 현장은 돌아갑니다. 체크인과 로테이션은 이벤트 서비스의 장부만으로 진행되기 때문입니다.
- **결제가 느려져도 신청 화면은 굳지 않습니다.** 나중에 결제 대행사(PG)를 연동했을 때 그쪽이 느려져도, 신청 화면 전체가 굳는 일은 없습니다.
- **매칭은 따로 고칩니다.** 매칭 규칙은 앞으로 가장 자주 손볼 부분입니다. 따로 두면 매칭을 고쳐 서버에 올리는 일(배포)이 현장 운영 기능을 흔들지 않습니다.

반대로 신청·정원·체크인·로테이션은 한 몸처럼 움직여야 하므로 이벤트 서비스 하나에 모았습니다. 자세한 근거는 [ADR-004 서비스 경계](../adr/ADR-004-service-boundary.md)에 있습니다.

## 5. 지금 어디까지 왔나

**기반 마무리(0단계)가 끝났고, 첫 기능인 회원 / 인증(1단계)까지 끝났습니다. 지금은 소개팅 상품 / 일정(2단계)을 설계하고 있습니다.** 저장소 구조, 앱과 서비스의 뼈대, 데이터베이스 연결, 자동 검사(CI), 문서와 협업 규칙까지 갖췄습니다. 참가자 웹에서 가입 · 로그인 · 내 프로필 · 비밀번호 변경 · 탈퇴가, 운영자 웹에서 로그인 · 회원 조회 · 계정 정지가 동작합니다([기능 소개서](./features/README.md)). 신청, 결제, 체크인, 매칭은 아직 없으며 아래 순서로 채워 갑니다.

| 단계 | 이름               | 한 줄 설명                                                                                 | 상태 |
| ---- | ------------------ | ------------------------------------------------------------------------------------------ | ---- |
| 0    | 기반 마무리        | 문서·협업 규칙·개발 환경 정리                                                              | 완료 |
