# @oneul-sai/contracts

서비스 간 API/Event 계약만 정의하는 패키지. 비즈니스 로직은 두지 않는다.

## 구조

| 경로          | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/http/`   | `ApiErrorResponse`(공통 에러 응답, `code?` 포함), `API_ERROR_CODES` · `ApiErrorCode`(SPEC-001 · SPEC-002 · SPEC-003 에러 코드 표)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `src/member/` | `Gender` · `MemberRole` · `AccountStatus` enum, 필드 규칙(`EmailSchema` · `PasswordSchema` · `PhoneSchema` …), 요청(`SignupRequest` · `UpdateMyProfileRequest` · `WithdrawRequest` · `MemberListQuery` · `UpdateMemberStatusRequest`), 응답(`MemberProfile` · `MemberSummary` · `MemberDetail` · `MemberListResponse`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `src/auth/`   | `ClientType`, 요청(`LoginRequest` · `RefreshRequest` · `LogoutRequest` · `ChangePasswordRequest`), 응답(`AuthResponse`), refresh 쿠키 이름 · 경로, JWT 고정 클레임, 내부 헤더 이름(`x-user-id` · `x-user-role` · `x-internal-token`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `src/events/` | `EventEnvelope`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `src/event/`  | 모임 상품 · 회차(SPEC-002). `ScheduleStatus` · `PublicScheduleStatus` enum, 필드 규칙 · 상수(`PRICE_*` · `CAPACITY_*` · `DEFAULT_CAPACITY_PER_GENDER` · `PAGE_MAX` · `SCHEDULE_BATCH_MAX` · 시각 상한 · `FORBIDDEN_TEXT_CHARS` · `VENUE_MAP_URL_HOSTS` · `isAllowedVenueMapUrl`), 요청(`CreateMeetupRequest` · `UpdateMeetupRequest` · `MeetupListQuery` · `CreateScheduleRequest` · `BatchCreateSchedulesRequest` · `UpdateScheduleRequest` · `UpdateScheduleStatusRequest` · `AdminScheduleListQuery` · `PublicScheduleListQuery`), 응답(`Meetup` · `PublicSchedule` · `AdminSchedule`(공개 스키마를 넓힌 것) · 목록 응답 · `BatchCreateSchedulesResponse`). 참가 신청(SPEC-003): `ApplicationStatus` · `ApplicationCancelledBy` enum, 목록 크기 상수 · `ApplicationIdSchema`, 요청(`CreateApplicationRequest` · `UpdateApplicationStatusRequest` · `MyApplicationListQuery` · `AdminApplicationListQuery`), 응답(`MyApplication` · `AdminApplication` · 목록 응답) |

스키마는 Zod v4. 이름은 설계서 7절의 필드 표와 같고, 각 스키마 `XxxSchema`에 `type Xxx = z.infer<...>`가 붙는다. 서비스는 `ZodValidationPipe`로 요청 스키마를 실행하고, 앱은 같은 스키마를 폼 검증(`zodResolver`)에 쓴다.

## 계약 규칙

- Producer/Consumer가 임의 payload를 만들지 않는다. 이 패키지에 정의된 계약 타입만 사용한다.
- 요청 스키마는 모두 `strictObject`다 — 모르는 필드는 400 `VALIDATION_FAILED`. 에러 message에 입력값을 되돌려 주지 않는다.
- 스키마가 거르지 않고 서비스가 별도 코드로 판정하는 규칙이 있다: 가입 연령(`birthYear ≤ 현재 연도 − SIGNUP_MIN_AGE` → `AGE_NOT_ALLOWED`), 필수 동의(`consents.privacy === true` → `CONSENT_REQUIRED`). 스키마는 형식(하한 · 타입)만 본다. 회차도 같다: 병합한 값의 시간 순서 · 진행 상한 · 바뀐 시각의 미래 · 선행 상한 · 공개 시 신청 마감(`SCHEDULE_TIME_INVALID`)과 남성 연령대 순서(`BIRTH_YEAR_RANGE_INVALID`)는 event-service가 판정한다. 참가 신청도 같다: 신청할 수 있는지(회차 상태 · 신청 마감 · 중복 · 입금 대기 한도 · 남성 연령대 · 성별 정원)와 본인 취소 가능 시각은 event-service가 판정한다.
- 요청 본문 스키마에는 `.default()`를 두지 않는다 — Zod 4는 `.partial()` 안의 기본값도 채우므로 PATCH가 보내지 않은 필드를 덮어쓴다. 빠진 선택 필드는 DB 기본값이 채운다.
- 응답 스키마는 `z.object`(모르는 키를 떼어 낸다)이고 요청 규칙을 재사용하지 않는다. 비공개 필드가 있는 응답은 공개 스키마를 `extend`로 넓혀 만든다(`omit`으로 줄이지 않는다).
- refresh · logout 본문의 `client`가 어느 쿠키(`REFRESH_COOKIE_NAMES[client]`)를 읽을지 정한다. 두 쿠키가 함께 있어도 오류가 아니다.
- 이벤트 이름은 `domain.event` 형식을 따르고, `EventEnvelope`의 `version` 필드로 버저닝한다. topic은 `match.created.v1` 형태를 쓴다.
- 초기 이벤트 후보 목록은 아래와 같고, 실제 구현 시점에만 타입으로 추가한다.
  - `member.created` / `member.withdrawn`
  - `application.created` / `application.accepted` / `application.cancelled`
  - `payment.completed` / `payment.failed` / `payment.cancelled`
  - `event.started` / `event.completed`
  - `rotation.started` / `rotation.changed` / `rotation.completed`
  - `preference.submitted`
  - `match.created`
